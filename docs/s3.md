# Armazenamento de Questões no Amazon S3 (Scripts SQL Puros)

## 1. Visão Geral
No **SQLArena**, todas as questões são armazenadas exclusivamente como **scripts SQL nativos** no bucket S3 `sqlarena-questions-bucket`. Não há arquivos CSV ou dados binários externos — toda a carga e definição de dados reside em comandos SQL do PostgreSQL.

### Estrutura de Objetos no S3
Cada questão possui seu próprio prefixo isolado:

```text
s3://sqlarena-questions-bucket/
└── questions/
    └── {question_id}/
        ├── schema.sql    # DDL: CREATE TABLE, CREATE INDEX, constraints
        ├── data.sql      # DML: INSERT INTO com dados de teste
        └── answer.sql    # Consulta gabarito oficial com ORDER BY
```

---

## 2. Papel de Cada Arquivo

| Arquivo | Função | Requisito Mandatório |
| :--- | :--- | :--- |
| `schema.sql` | Define a estrutura do banco e tipos de dados no schema isolado | Chaves primárias e relacionamentos |
| `data.sql` | Popula o banco com os registros sobre os quais a query será executada | Volume suficiente para validar filtros e joins |
| `answer.sql` | Consulta gabarito canônica elaborada pelo instrutor | **DEVE conter ORDER BY** para garantir determinismo |

---

## 3. Métodos Disponíveis no `S3Manager`

Arquivo: `app/s3/s3_manager.py`, classe `S3Manager`.

```python
from app.s3.s3_manager import S3Manager

s3 = S3Manager()
s3.ensure_bucket_exists()

# 1. Salvar os 3 scripts de uma questão no S3
keys = s3.upload_question_sql_files(
    question_id=10,
    schema_sql="CREATE TABLE ...",
    data_sql="INSERT INTO ...",
    answer_sql="SELECT ... ORDER BY ...",
)

# 2. Ler o conteúdo em texto puro dos 3 arquivos
files = s3.get_question_sql_files(question_id=10)
# Retorna: {'schema': str, 'data': str, 'answer': str}

# 3. Baixar os scripts para disco local (usado no Bootstrapping dos Workers EC2)
downloaded = s3.download_question_sql_files(question_id=10, target_dir="/tmp/pergunta_10")
# Baixa: /tmp/pergunta_10/schema.sql, data.sql e answer.sql

# 4. Excluir todos os arquivos da questão (deleção atômica)
s3.delete_question_files(question_id=10)
```

---

## 4. Integração com a Camada de Workers (Bootstrapping)

Quando uma nova instância EC2 da Camada de Processamento (ASG 2) inicializa ou recebe notificação de publicação:

1. O Worker consulta as questões publicadas no RDS.
2. Faz o download dos scripts SQL (`schema.sql` e `data.sql`) do S3.
3. Executa os scripts no PostgreSQL local dentro do schema exclusivo `pergunta_{id}`:
   ```sql
   CREATE SCHEMA IF NOT EXISTS pergunta_10;
   SET search_path TO pergunta_10;
   -- Executa schema.sql
   -- Executa data.sql
   ```
4. A partir deste ponto, o ambiente local da máquina está pronto para avaliar qualquer consulta de aluno submetida àquela questão em microssegundos.

---

## 5. Exclusão Atômica de Questão

Quando um instrutor remove uma questão pelo painel:
1. O backend remove a questão do RDS.
2. O método `s3.delete_question_files(question_id)` remove em lote todos os objetos sob o prefixo `questions/{id}/`.
3. Uma mensagem de controle é enviada via fila SQS para que todos os Workers executem `DROP SCHEMA IF EXISTS pergunta_{id} CASCADE;` localmente.
